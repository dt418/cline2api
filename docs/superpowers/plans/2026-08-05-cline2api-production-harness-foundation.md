# cline2api Production Harness Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Initialize a cross-platform TypeScript monorepo with the approved Production Harness and a tested core package baseline.

**Architecture:** Keep `AGENTS.md` as the canonical agent instruction layer, keep mutable session state in `.harness/`, and expose one package-manager command for bootstrap. Use a small `@cline2api/core` package as the first independently testable workspace unit; defer provider execution, streaming translation, and external integrations to later feature plans.

**Tech Stack:** Node.js 24+, pnpm 11+, TypeScript 5, Vitest, Prettier, native Node.js `child_process`, Git.

## Global Constraints

- Use only documented, official Cline CLI behavior at the future Cline boundary.
- Do not reverse engineer Cline or ClinePass internal protocols.
- Preserve streaming-first, OpenAI-compatible, plugin-first and backward-compatible boundaries.
- Support Windows, macOS and Linux; canonical bootstrap logic must run through Node.js, not POSIX-only shell code.
- Redact secrets before writing evidence, logs, snapshots, commits or CI artifacts.
- Keep exactly one `in_progress` feature in `.harness/feature_list.json`.
- This foundation commit does not implement the provider adapter or external router integrations.
- The implementation phase follows the project-owner instruction to use Luna with ultra reasoning.

### Task 2: Add the machine-readable harness state validator

**Files:**

- Create: `scripts/harness/validate-harness.mjs`
- Test: `scripts/harness/validate-harness.test.ts`

**Interfaces:**

- Produces `validateFeatureList(payload): { valid: boolean; errors: string[] }`.
- The validator accepts `{ version: 1, features: Feature[] }` and rejects an invalid status, more than one `in_progress` feature, a `passing` feature without evidence, missing IDs, and duplicate IDs.

- [ ] **Step 1: Write the failing validator tests**

Create tests with these behaviors:

```ts
import { describe, expect, it } from "vitest";
import { validateFeatureList } from "./validate-harness.mjs";

const feature = (id: string, status: string, evidence = "") => ({
  id,
  priority: 1,
  area: "harness",
  title: "Example",
  user_visible_behavior: "The harness is verifiable",
  status,
  dependencies: [],
  verification: ["pnpm verify"],
  evidence,
  notes: "",
});

describe("validateFeatureList", () => {
  it("accepts one in-progress feature and passing evidence", () => {
    expect(
      validateFeatureList({
        version: 1,
        features: [
          feature("HARN-001", "in_progress"),
          feature("CORE-001", "passing", "tests: pass"),
        ],
      }),
    ).toEqual({ valid: true, errors: [] });
  });

  it("rejects multiple in-progress features", () => {
    const result = validateFeatureList({
      version: 1,
      features: [feature("HARN-001", "in_progress"), feature("CORE-001", "in_progress")],
    });
    expect(result.valid).toBe(false);
    expect(result.errors).toContain("only one feature may be in_progress");
  });

  it("rejects passing features without evidence", () => {
    const result = validateFeatureList({ version: 1, features: [feature("CORE-001", "passing")] });
    expect(result.valid).toBe(false);
    expect(result.errors).toContain("CORE-001: passing features require evidence");
  });
});
```

### Task 3: Implement cross-platform harness bootstrap

**Files:**

- Create: `scripts/harness/harness-init-lib.mjs`
- Test: `scripts/harness/harness-init-lib.test.ts`
- Create: `scripts/harness-init.mjs`
- Modify: `package.json`

**Interfaces:**

- Produces `getPackageManagerCommand(platform): string`, returning `pnpm.cmd` on Windows and `pnpm` elsewhere.
- Produces `getInstallArgs(hasLockfile): string[]`, returning `['install', '--frozen-lockfile']` when a lockfile exists and `['install']` otherwise.
- `scripts/harness-init.mjs` reads `.harness/feature_list.json`, validates it, optionally installs dependencies, and runs `pnpm verify`.
- `HARNESS_SKIP_INSTALL=1` skips installation for deterministic CI and local verification runs.


- [ ] **Step 3: Implement the helper and bootstrap entrypoint**

Implement the two pure helpers, then make `harness-init.mjs`:

1. resolve the repository root from `import.meta.url`;
2. read and parse `.harness/feature_list.json`;
3. exit non-zero with deterministic validation errors when state is invalid;
4. run the platform-specific pnpm executable with the lockfile-aware install args unless `HARNESS_SKIP_INSTALL=1`;
5. run `pnpm verify`, forwarding its exit status;
6. print the standard `pnpm dev`, `pnpm test`, and `pnpm verify` commands after success.

Use `spawnSync` with inherited stdio, never shell interpolation, and never print environment secrets.
